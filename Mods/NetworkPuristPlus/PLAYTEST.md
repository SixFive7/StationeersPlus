# Network Purist Plus Playtests

Implemented changes awaiting in-game confirmation. An agent records a playtest here, not in `TODO.md`, when it has changed code whose behavior can only be confirmed by running the game: single-player, a hosted multiplayer session, or the dedicated server under `DedicatedServer/`. This keeps `TODO.md` a list of work still to do, and gives one place to check whether a change already has a pending test before adding another.

Rules:
- Add an entry when code is implemented but its in-game behavior is unconfirmed. Write down everything a tester needs: what changed (commit if there is one), single-player vs multiplayer / dedicated-server, the save or world to set up, the exact in-game steps, what to watch (InspectorPlus request files, specific log lines, on-screen behavior, IC10 reads), and the expected result. Point at any staged `.work/<date>-<slug>/` request files or playbook.
- Check first. Before adding, scan the entries below so a change already covered by a pending test is not duplicated; extend the existing entry instead.
- Remove an entry when one of these happens: a run confirms it works; a run shows it broken (then add a fresh `TODO.md` item for the fix, or keep working on it now); or the player says the playtest is done. Entries are plain bullets, not checkboxes: like `TODO.md`, finished items are removed, not ticked off. Outcomes live in git history.

- **Console-output rework for the player-facing helpers (commit `0e99bf11`, with the `RESEARCH.md` write-up in `b494e73f` and review follow-ups on top, 2026-07-27), extended by the migration onto the shared `PlayerMessage` helper (2026-07-29).** `PlayerLog` / `PlayerWarn` / `PlayerError` in `Plugin.cs` changed and were then deleted outright, plus their callers. One session covers both: the same lines are on screen either way, so test them together.
  - What changed in the migration (2026-07-29). `Plugin.cs` no longer defines its own helpers; `Patterns/Console/PlayerMessage.cs` is linked into the build and `Awake()` calls `PlayerMessage.Init("Network Purist Plus", Logger)`. All 15 player-facing call sites now pass an explicit key and throttle. **Message text is unchanged everywhere; the bracketed prefix is not.** The two hand-rolled one-shot bools (`CableRollOnConstruct._loggedError`, `ClampNegativeMergeQuantityPatch`'s `_clampCount == 1`) are now `Throttle.Once`, and the previously uncapped Stationpedia re-hide warning is now `Throttle.CapWithSummary(3)`.
  - What changed. `PlayerError` no longer calls `UnityEngine.Debug.LogError`: the console re-prints `LogType.Error` itself (it subscribes to `Application.logMessageReceivedThreaded`), so every error was being shown to the player twice, once as the controlled `PrintError` and again lowercased with a stack trace. `PlayerWarn` now prints yellow via `PrintAction` instead of red via `PrintError`, since a warning is not an error and the game has no `PrintWarning`. A new `PlayerError(string, Exception)` overload sends the full exception to the file log and only the type and message to the console, and the plugin's own init-failure catch now uses it instead of interpolating a bare exception. In `ReplaceLongPiecesOnLoadPatch` all three per-piece lines moved to the file log (the "rebuilding ..." success line in `0e99bf11`, and the footprint-skip and rebuild-failure lines in the review pass that followed, which had been left player-facing in the same loop); the per-cable align failure in `NormalizeCableRollOnLoadPatch` moved likewise; `CableRollOnConstruct` gained a one-shot guard on its failure path to match the one already on its success path.
  - Mode: single-player first (host counts), then a hosted session if convenient. Needs a world containing long pipe or cable variants so the on-load rebuild sweep actually runs.
  - Case A, the on-load sweep: load a save with a decent number of long pieces (the more the better; a few dozen is a good stress) and watch the console during the load. Expect the summary lines only, "found N long piece(s) to rebuild..." and "done: rebuilt N ... as M single-tile segment(s)...", plus the cable-alignment summary. Previously there was also one line per long piece, each forced onto the closed-console overlay, which blanketed the screen on a large world. The per-piece detail should now appear only in `BepInEx\LogOutput.log`. Confirm the console is readable immediately after load rather than being full of this mod's output.
  - Case B, warning colour: any `PlayerWarn` line must now render YELLOW, not red. These are hard to trigger on demand (they fire on a footprint or alignment failure), so the practical check is simply that no line the mod prints is red unless it is genuinely an error. If a warning does appear, it should be yellow and carry no stack trace.
  - Case C, the build-time one-shot: place straight cables normally, including a ZoopMod drag across several cells if available. The alignment path runs on every placement. Expect NO console output at all on the normal success path. If the canonicalisation ever throws, expect exactly ONE yellow line ending "Further occurrences go to the log only.", and nothing more no matter how many cables follow.
  - Case D, the prefix (new, and the one thing an existing player will notice): every line the mod prints must now start `[Network Purist Plus]`, with spaces, not `[NetworkPuristPlus]`. The startup status line at load is the easiest place to read it. Confirm the same prefix appears on the BepInEx log lines and, if StationeersLaunchPad's boot panel is visible during the splash, there too. Nothing should print with both spellings.
  - Case E, the Stationpedia re-hide cap (new): this path only fires if another mod's Stationpedia page override clears `HideInStationpedia` on a long variant, so it is not directly triggerable in a vanilla load. The check is negative: with no such mod installed, opening the Stationpedia and switching the game language (which re-runs `Stationpedia.PopulateLists`, and with it the postfix) must produce NO output from this mod at all. If a warning ever does appear, it must stop after three lines and be followed by one "N more not shown" summary, no matter how many long variants exist.
  - Case F, the startup line count (new): the four startup wordings share one throttle key, so exactly one line must appear at load. Flip the master toggle `Enable Network Purist Plus` off, restart, and confirm exactly one yellow "the master toggle ... is OFF" line, then turn it back on and confirm exactly one "vN.N.N active: ..." line. Never two.
  - Watch for: any line appearing twice in the console, which would mean a `Debug.LogError` pairing survived somewhere; and a multi-line stack trace in the console, which would mean a caller is still interpolating a bare exception instead of using the `PlayerMessage.Error(string, Throttle, string, Exception)` overload.
  - Log-side check: BOTH sweep summaries now end their failure tail with "(N failed -- see the log)". The cable-alignment one (`NormalizeCableRollOnLoadPatch`) previously said "see warnings above"; the long-piece one (`ReplaceLongPiecesOnLoadPatch`) previously said "see warnings/errors above". Both were changed because the per-item detail they pointed at is no longer on screen. Confirm the detail really is in `LogOutput.log` and that neither summary still points at "above".
  - Also worth confirming while here, an old outstanding item from `RESEARCH.md`: no HarmonyX "Could not find type named Util.Commands.ConsoleWindow" warning at startup.
